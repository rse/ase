# Measurements of the `ase-repo-review` effectiveness test

This file is a log. Each measurement series is appended by
`node benchmark/repo-review/compare.mjs --journal MEASUREMENTS.md --title "..." <result folders>`
with the values computed at that time. Existing entries are never rewritten:
corrections and re-scorings are added as dated notes or as new entries. The
manual reading of a series is written by hand below its generated part. The
series title and the configuration table of an entry name the test case; the two
entries of 2026-11-03 below predate the second case and belong to `shop-core`.

## Overview

All automated figures are location-matched: a finding counts only if it names the
file and lines recorded in the expected-results list (see the README, "Scoring and
limitations"). Values are means over the evaluated runs of a configuration.

### Manual reading

against the expected-results list (one reader, not independently verified).
Run labels as in the table "Runs" above: R1–R3 Sonnet, R4–R6 Opus.

**Context of the series.** This was the first measurement with the benchmark.
Two earlier Sonnet plumbing runs with the original invocation are not included:
`20261103T071925Z` was stopped by the isolation check, and `20261103T072901Z` was
`unparseable` because the sub-agent was not allowed to run `git`; both led to the
isolation setup and tool permissions described in `DESIGN.md`. The whole

translated to English keys and values afterwards by a fixed mapping (field
`migrated`); transcripts and reviews are untouched, and every figure is identical
before and after. The expected-results list was likewise translated and later
given short titles, which explains the two digests in the configuration; its
entries and locations are unchanged. The thresholds were committed in
`c3f00a57` before the first paid run; `f03489e6` only translated the `source` text
of `thresholds.json`.

Result: Opus 0 and Sonnet 2 false alarms on decoys out of 12 decoy chances each.
The unassignable findings listed above were not classified.

**Conclusion.** The automated ceiling-effect check says "adequate", which only
means that no ceiling effect was detected. On reading, Opus found every defect in
every run, so the case is too easy for Opus, and the scorer, not the model,
accounts for most of the gap between the automated figures and the reading.

**Recommended improvements before the next series** (not implemented):

- Parse locations with several ranges, such as `order.ts:29,51-52`, completely.
- Expected-results list: add the declaration or the call where models typically
  place the same defect (for example B-04 also `order.ts:29`, B-02 also the call
  `discount.ts:34`), keeping the minimum distance to decoys.
- Place decoys further away from genuine, non-seeded weaknesses of the code
  (K-04 next to the hard-coded currency, K-01 next to the percentage defect).
- Count wide ranges (more than 10 lines) separately instead of assigning them by
  overlap.
- Add harder, independent cases before using results as a statement about
  open-weight models.

### Manual reading

Written by hand on 2026-11-03. Same runs and same reviews as the entry
"2026-11-03: Reference measurement, Claude Opus 5.5 and Claude Sonnet 5.5"; only
the scorer changed. That entry stays as it was and keeps the original figures.

**What changed.** The parser used to read only the first range of a location
that lists several, such as `src/order.ts:29,51-52`. It now reads all ranges, and
a finding is matched if any of them fits. In R5 and R6, Opus named B-04 at
`order.ts:29,51-52`; R5 now counts B-04 as found, R6 already had it through
another finding, so the second one is now a duplicate instead of unassignable.
Sonnet is unaffected.

**Effect on the figures.** Opus: location-matched recall overall 0.90 → 0.95,
medium 0.89 → 1.00, unassignable findings per run 1.0 → 0.3. Sonnet: unchanged.
The pilot-threshold verdicts and the ceiling-effect statement stay the same.

**Manual reading.** Unchanged from the earlier entry: Opus 21 of 21 defects and 0
false alarms on decoys, Sonnet 20 of 21 and 2. The remaining gap for Opus is B-02
in R6, described correctly but located at the call (`discount.ts:33-34`) instead
of in `percentOff`; that is a limit of matching by location, not a parser defect.
